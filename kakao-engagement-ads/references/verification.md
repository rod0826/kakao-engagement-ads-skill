# 저장 결과 확인과 복구

이 스킬은 2026-10-07 공식 문서에 근거해 작성했다. 파일 구조·YAML·내부 참조를 검증했고, 같은 날 Chrome에서 방문·디스플레이 캠페인·광고그룹·이미지 네이티브 소재 등록과 기존 완료 비즈니스폼+ 연결을 실제 실행했다. 목록 재조회와 저장 후 소재 미리보기의 PC·모바일 폼 ID를 확인했다. 이번 경로의 등록 검증을 모든 광고 유형이나 실운영 성공으로 확대하지 않는다.

## 단계별 완료 근거

| 작업 | 확인할 근거 |
|---|---|
| 캠페인 | 대상 계정의 목록/상세, 이름·ID, 목표·유형, 연동 픽셀 & SDK, 예산·운영 상태 |
| 광고그룹 | 올바른 상위 캠페인, 이름·ID, 타겟·디바이스·지면·입찰·일예산·기간·운영 상태 |
| 소재 | 올바른 그룹, 이름·ID, 등록된 자산·문구·미리보기, 연결 폼, 심사·운영 상태 |
| 폼 연결 | 저장 후 상세에 표시되는 폼 이름/ID와 랜딩 미리보기 |
| 미저장 초안 | 입력한 편집 탭 유지, 아직 실행하지 않은 저장 동작과 남은 필수값 |

저장 후 목록이 늦게 반영되면 대상 이름·경로·ID로 조회한다. 조회 실패는 생성 실패의 증거가 아니므로 재생성 전에 목록과 상세를 확인한다. 성공 토스트만 있고 목록/상세를 못 확인하면 ‘저장 응답 확인, 등록 결과 확인 미완료’로 보고한다.

입력 값은 저장 후 주요 항목을 대조한다. 비활성 버튼은 필수 필드·오류 안내·권한·지원 조합을 확인하고 정상 경로로 해결한다. 오류가 지속되면 현재 초안과 오류 내용을 보존하고 사용자에게 필요한 조치만 설명한다.

브라우저 제어가 중단되면 원래 탭의 URL·제목·초안을 확인한 후 이어서 진행한다. 미저장 내용을 버릴 수 있는 재로드·닫기는 하지 않는다. 다른 창이 활성화되었다고 입력 대상을 바꾸지 않는다. 재시도 전에 이미 저장되었는지 확인한다.

공개용 캡처는 계정명·ID·사업자 정보·응답·인증정보를 노출하지 않는 예시 영역만 사용하고 이미지를 직접 확인한다. 사용자에게 결과를 보고할 때의 계정 ID 확인과 공개 저장소에 계정 ID를 넣는 행위는 구분한다.

## 실행한 범위와 한계

- 실행: 기존 픽셀 선택, 캠페인 일예산 설정, 방문 자동입찰의 클릭수 최대화, 그룹 일예산·미래 시작/종료일 설정, 기존 이미지 라이브러리 선택, 소재 문구·버튼·설명 입력, 기존 완료 폼 미리보기·선택, 개별 설정완료와 전체 저장, 목록·상위 경로 재조회, 저장된 소재 미리보기의 PC·모바일 랜딩 확인.
- 실행: 생성한 캠페인·그룹·소재 각각의 ON/OFF 토글을 OFF로 변경하고 체크 해제 반영 확인. 검증 화면의 비용·노출수는 0이었다.
- 미실행: 전환 목표·비즈보드·수동입찰·동영상·다른 타겟 조합, 새 폼 생성·최종 완료·임시폼 연결, 신규 이미지 업로드·에디터, 광고 충전·집행·실제 응답 제출·심사 승인.

대시보드의 상태 열에 OFF/운영 불가라고 표시되어도 해당 항목의 ON/OFF 토글은 켜져 있을 수 있다. 이번 계정은 잔액 부족으로 운영 불가였고 새 항목의 토글은 기본 ON이었다. 비집행 테스트는 잔액 부족이나 심사 미승인에 의존하지 않고 생성한 캠페인·그룹·소재의 토글을 직접 OFF로 만들며 다른 기존 항목이나 계정 전체를 바꾸지 않는다. 소재 등록 전에 새 캠페인 OFF를 확인하고 최종 결과에서 하위 토글도 확인한다.

이름·썸네일이나 아이콘은 접근성 트리와 DOM에서 역할이 다르게 표시될 수 있다. 링크 역할로 찾을 수 없으면 현재 화면의 텍스트·DOM을 다시 확인하고 관찰한 실제 컨트롤을 사용한다. 저장 직후 빈 목록은 로딩일 수 있으므로 완료 상태를 재조회한다.

## 2026-10-08 회사 PC 사용자 테스트 피드백

[이슈 #1](https://github.com/rod0826/kakao-engagement-ads-skill/issues/1)에서 기존 소재 편집창을 열어 둔 채 별도 화면에서 폼을 작성 완료한 뒤, 폼 선택 영역 내부 새로고침으로 대상 폼이 표시된 사례가 1회 보고되었다. 폼 선택과 랜딩 미리보기까지 확인했으며 내부 원인은 확인하지 않았다. 이를 전체 페이지 재로드나 폼 재생성 없이 목록만 갱신하는 절차로 반영했다.

[이슈 #2](https://github.com/rod0826/kakao-engagement-ads-skill/issues/2)에서 프로필 이미지 라이브러리에 최근 사용 이미지가 없고 사용자 파일도 준비되지 않아 테스트가 중단된 사례가 보고되었다. 홍보 이미지 라이브러리의 준비 상태는 확인되지 않았다. 캠페인·그룹은 생성 후 OFF로 설정했지만 소재는 미저장 상태였다. 신규 업로드는 시도하지 않았으며 소재 최종 저장·저장 후 폼 연결·심사 상태도 이 세션에서는 검증하지 않았다. 이는 2026-10-07의 기존 이미지·기존 완료 폼을 사용한 저장 검증과 별개다.

수정 지침은 필수 자산 확인 시점과 목록 갱신 절차를 보완한다. 이번 수정 과정에서는 파일 구조·참조·변경 범위를 확인했으며, 회사 PC 경로를 새로 재실행하거나 이미지 업로드·최종 저장을 추가 검증한 것은 아니다. 자산 부족으로 중단하면 저장된 캠페인·그룹의 확인된 운영 상태, 미저장 소재와 보존한 입력, 프로필·홍보 이미지 각각의 준비/부족/미확인 상태와 재개 조건을 보고한다.
