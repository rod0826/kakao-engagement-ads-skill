# 저장 결과 확인과 복구

이 스킬은 2026-10-07 공식 문서에 근거해 작성했다. 배포 전 파일 구조·YAML·내부 참조를 검증했다. 실제 카카오 계정에서 캠페인·그룹·소재 저장, 폼 연결, 심사, 광고 집행은 이번 제작 과정에서 실행하지 않았다. 화면 실측 규격이나 실운영 성공을 주장하지 않는다.

## 단계별 완료 근거

| 작업 | 확인할 근거 |
|---|---|
| 캠페인 | 대상 계정의 목록/상세, 이름·ID, 목표·유형, 연동 픽셀 & SDK, 예산·운영 상태 |
| 광고그룹 | 올바른 상위 캠페인, 이름·ID, 타겟·디바이스·지면·입찰·일예산·기간·운영 상태 |
| 소재 | 올바른 그룹, 이름·ID, 등록된 자산·문구·미리보기, 연결 폼, 심사·운영 상태 |
| 폼 연결 | 저장 후 상세에 표시되는 폼 이름/ID와 랜딩 미리보기 |
| 미저장 초안 | 입력한 편집 탭 유지, 아직 실행하지 않은 저장 동작과 남은 필수값 |

저장 후 목록이 늦게 반영되면 대상 이름·경로·ID로 조회한다. 조회 실패는 생성 실패의 증거가 아니므로 재생성 전에 목록과 상세를 확인한다. 성공 토스트만 있고 목록/상세를 못 확인하면 ‘저장 응답 확인, 등록 결과 확인 미완료’로 보고한다.

입력 값은 저장 후 주요 항목을 대조한다. 비활성 버튼은 필수 필드·오류 안내·권한·지원 조합을 확인하고 정상 경로로 해결한다. 오류가 지속되면 현재 초안과 오류 내용을 보존하고 사용자에게 필요한 조치만 설명한다.

브라우저 제어가 중단되면 원래 탭의 URL·제목·초안을 확인한 후 이어서 진행한다. 미저장 내용을 버릴 수 있는 재로드·닫기는 하지 않는다. 다른 창이 활성화되었다고 입력 대상을 바꾸지 않는다. 재시도 전에 이미 저장되었는지 확인한다.

공개용 캡처는 계정명·ID·사업자 정보·응답·인증정보를 노출하지 않는 예시 영역만 사용하고 이미지를 직접 확인한다. 사용자에게 결과를 보고할 때의 계정 ID 확인과 공개 저장소에 계정 ID를 넣는 행위는 구분한다.
